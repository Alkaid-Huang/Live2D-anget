## 3. 核心模型

### 3.1 模式复用：06.2 的三件套原样搬过来

```
06.2 的 VAD 三件套                    06.4 的 ASR 三件套
─────────────────────               ─────────────────────
VADInterface (ABC)      ──对照──>   ASRInterface (ABC)
create_vad() 工厂        ──对照──>   create_asr() 工厂
ServiceContext.init_vad() ──对照──>  ServiceContext.init_asr()
```

**【类比/解释】** 你 06.2 学会的是"怎么开一家餐厅"（工厂=厨师、配置=菜单、容器=经理）。本课不是再学一遍开餐厅，而是**开第二家分店**：换掉招牌（ASR 替代 VAD），流程一模一样。真实项目里，TTS、LLM 都是第三、第四家分店。

### 3.2 延迟导入：可选依赖的标准做法

```python
# 不好的做法：一 import 就炸
from sherpa_onnx import ...   # 用户没装 → 整个包 import 失败 → mock 也用不了

# 好的做法：真实后端延迟到"真正用到时"才导入
def _ensure_backend_loaded(asr_type):
    if asr_type in ("sherpa_onnx", "faster_whisper"):
        importlib.import_module(f"echo.asr.{asr_type}_asr")
```

`echo/asr/__init__.py` 里用 `try/except ImportError` 包裹真实后端的导入：装了就注册，没装就跳过。**mock 后端永远可用**，测试不依赖真实模型。

### 3.3 接口默认实现：异步包装只写一次

```python
class ASRInterface(ABC):
    # 整条 VAD→ASR 管线的统一约定：16kHz 单声道
    SAMPLE_RATE = 16000
    NUM_CHANNELS = 1
    SAMPLE_WIDTH = 2

    @abstractmethod
    def transcribe_np(self, audio_np) -> str: ...

    async def async_transcribe_np(self, audio_np) -> str:
        # 默认实现：先统一转 float32，再扔进线程池，后端不用重复写
        if audio_np.dtype != np.float32:
            audio_np = audio_np.astype(np.float32)
        return await asyncio.to_thread(self.transcribe_np, audio_np)
```

**【类比/解释】** 接口像合同：后端（乙方）只承诺"给我音频，还你文字"（同步版）。异步包装是甲方提供的统一服务（把同步调用塞进线程池），乙方不必每家都自己实现一遍异步。

> 💡 **为什么接口不收 sample_rate？** 真实项目（Open-LLM-VTuber）的做法是：采样率写死为接口常量 `SAMPLE_RATE = 16000`，整条管线在源头统一转成 16k。**统一约定比每次传参更省心**——传参意味着"每个调用点都可能传错"，常量意味着"错不了"。你的 VAD（课题06.1/06.2）和 ASR 都吃 16k 音频，正好是同一个约定。[来源：一手源 `src/open_llm_vtuber/asr/asr_interface.py`（2026-08-13 检索）]

### 3.4 VAD → ASR 流水线

```
麦克风音频块(16k) → VAD.detect_speech() → 完整语音段(bytes) → ASR.transcribe_np() → 文本
      │                                    │                       │
   流式帧                             状态机确认"说完了"        转成字符串
```

本课先用 mock 版跑通链路，真实后端在「进阶任务」接入。

## 4. 关键概念与例子

### 4.1 两个真实后端：SenseVoice vs faster-whisper

| 维度 | sherpa-onnx + SenseVoice | faster-whisper |
|------|--------------------------|----------------|
| 本质 | ONNX Runtime 离线推理框架，加载 SenseVoice 模型 | Whisper 的 CTranslate2 高性能重实现 |
| 语言 | 中文、英文、粤语、日文、韩文 + 多种中文方言 | 多语言（Whisper 系列），中文识别也强 |
| 中文场景 | 中文优先，速度快，项目预设 | 多语言均衡，GPU 加速明显 |
| 硬件 | CPU 友好（int8 量化） | NVIDIA GPU 加速明显，Mac 不支持 GPU |
| 模型体积 | 小（数百 MB 级） | small 约 244M 参数 |

**【事实】** sherpa-onnx 是 k2-fsa 的离线推理框架，支持 Transducer、Paraformer、SenseVoice 等架构，SenseVoice 小模型支持中英粤日韩及中文方言。[来源：一手源 sherpa-onnx 官方文档（2026-08-13 检索）]

**【事实】** faster-whisper 是 Whisper 的 CTranslate2 重实现；4060 8GB 实测（22 秒音频，int8）：small 模型 CPU 1.56s / GPU 0.48s，官方建议 8GB 显存优先 small。[来源：一手源 Open-LLM-VTuber 官方文档 ASR 页（2026-08-13 检索）]

### 4.2 设备降级（对照 06.2 的 create_vad_with_fallback）

faster-whisper 支持 `device="auto"`，会自动选择可用设备；但如果配置里硬写了 `cuda` 而机器没有 GPU，创建模型时会抛错。`create_asr_with_fallback()` 捕获设备相关错误后用 `device="cpu"` 重试——这就是 06.2 学的降级模式第二次使用。

> **对照真实源码**：Open-LLM-VTuber 的 sherpa-onnx 后端在 `__init__` 里用 `onnxruntime.get_available_providers()` 检查 CUDA 是否可用，`provider` 配了 `cuda` 但没有 CUDA 时直接回退 CPU 并打警告日志。[来源：一手源 `src/open_llm_vtuber/asr/sherpa_onnx_asr.py`（2026-08-13 检索）]

### 4.3 模型管理：两种策略

- **faster-whisper**：`WhisperModel("small", download_root="models/whisper")` 首次运行自动从 Hugging Face 下载，之后复用本地缓存
- **sherpa-onnx + SenseVoice**：模型是**单模型文件** `model.onnx`（或量化版 `model.int8.onnx`）+ `tokens.txt`，不是 encoder/decoder 双文件。官方发布包是 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2`，解压到 `models/` 目录。[来源：一手源 sherpa-onnx 官方 SenseVoice Python API 文档（2026-08-13 检索）]
  - 真实项目会**自动下载**：`download_and_extract()` 先查本地是否已有模型，没有就下载 tar.bz2 并解压。[来源：一手源 `src/open_llm_vtuber/asr/utils.py`（2026-08-13 检索）]
  - 本课把它简化为：代码在加载前做文件存在性检查，缺失时给出清晰的 `FileNotFoundError`（TODO 6）。自动下载列为**可选进阶**，想挑战可以自己补一个 `download_model()`。

### 4.4 SenseVoice 元数据标签（真实项目踩过的坑）

SenseVoice 家族模型的输出**可能**带元数据标签，例如：

```
<|zh|><|NEUTRAL|><|Speech|><|woitn|>欢迎大家来体验达摩院推出的语音识别模型
```

`<|zh|>` 是语言、`<|NEUTRAL|>` 是情感、`<|Speech|>` 是事件——它们不是用户说的话。真实项目在 FunASR 后端用 `re.sub(r"<\|.*?\|>", "", text)` 剥离（还处理了一种带空格的异常形态 `< | zh | >`）。[来源：一手源 `src/open_llm_vtuber/asr/fun_asr.py`（2026-08-13 检索）]

本课把这段清洗逻辑抽成 `text_utils.clean_sensevoice_text()`（完整提供），并要求 sherpa-onnx 后端的 `transcribe_np` 转写后调用它——这样既能单测，又和真实项目"识别后必清洗"的手感一致。

### 坑 1：真实后端 import 拖垮整个包

```python

# ✅ try/except 包裹，或延迟到工厂里 importlib
```

### 坑 2：接口把异步逻辑写进抽象方法

```python
# ❌ 每个后端都要自己写 async 包装，重复代码
# ✅ 异步包装放接口默认实现，后端只写同步 transcribe_np
```

### 坑 3：VAD 和 ASR 的输入输出类型对不上

VAD 吐 `bytes`，ASR 吃 `numpy` 数组。衔接时要么在中间转换，要么约定接口文档写清楚。mock 流水线测试就是帮你提前暴露这种错位。

### 坑 4：凭记忆写第三方 API 参数

```python
# ❌ 从记忆里抄 sherpa-onnx / faster-whisper 的参数名
# ✅ 本课 TODO 6/7 明确要求：先检索官方文档再填
```

这是演化知识的纪律：**先查再写，不查不写**。

具体到本课，两个最容易记错的点：
- **faster-whisper 的 `transcribe` 对 numpy 输入不需要传采样率**——音频必须是 16k float32（接口契约），采样率由 `ASRInterface.SAMPLE_RATE` 保证，而不是靠参数传。
- **faster-whisper 支持 `initial_prompt`**（配置里的 `prompt` 字段）：给识别提供上下文，语言应与音频一致。真实项目还会传 `condition_on_previous_text=False`。[来源：一手源 `src/open_llm_vtuber/asr/faster_whisper_asr.py`（2026-08-13 检索）]

### 坑 5：真实后端没有降级路径

配置写 `provider="cuda"`，用户没 GPU → 程序崩溃且没有提示。`create_asr_with_fallback` 就是补这条路径。

### 坑 6：SenseVoice 标签没剥离，文本被污染

```python
# ❌ 直接把 stream.result.text 返回
#   → LLM 会看到 "<|zh|><|NEUTRAL|>你好"，对话体验瞬间崩坏
# ✅ 先过 clean_sensevoice_text() 再返回
```

### 坑 7：sherpa-onnx 在 Windows 中文路径下会崩（旧版本）

sherpa-onnx 早期在 Windows 上用窄字符 API 读写文件路径，模型放在中文目录（如 `D:\模型\...`）会加载失败。sherpa-onnx v1.13.4（2026-07-06 发布）改用宽字符 API + `std::filesystem` 修复了这个问题。[来源：一手源 sherpa-onnx v1.13.4 Release Notes，PR #3255（2026-08-13 检索）]

**实践建议**：模型目录统一用纯英文路径（如 `models/...`），既是习惯，也避免踩到老版本/其他平台同类问题的边。

## 附录：源码对照学习指引

学完本课后，对照 Open-LLM-VTuber 真实源码回答：

1. **Open-LLM-VTuber 是怎么做的？**
   - **接口**：`ASRInterface` 定义 `SAMPLE_RATE = 16000` 常量，`transcribe_np(audio)` 只收音频不收采样率；`async_transcribe_np` 默认实现统一转 float32 后用 `asyncio.to_thread` 包装。[来源：一手源 `src/open_llm_vtuber/asr/asr_interface.py`（2026-08-13 检索）]
   - **sherpa-onnx 后端**：`VoiceRecognition(ASRInterface)` 支持 8 种 `model_type`（transducer / paraformer / sense_voice / whisper 等）；SenseVoice 用**单模型文件** `sense_voice`（model.onnx）+ `tokens` 调 `OfflineRecognizer.from_sense_voice(...)`；`provider="cuda"` 时用 `onnxruntime.get_available_providers()` 检查，没有 CUDA 自动回退 CPU；模型缺失时自动下载（`download_and_extract()`）。[来源：一手源 `src/open_llm_vtuber/asr/sherpa_onnx_asr.py` + `asr/utils.py`（2026-08-13 检索）]
   - **faster-whisper 后端**：配置参数是 `model_path` / `download_root` / `language` / `device` / `compute_type` / `prompt`；`transcribe(audio, beam_size=5, language=..., condition_on_previous_text=False, initial_prompt=prompt)`，numpy 输入默认 16k。[来源：一手源 `src/open_llm_vtuber/asr/faster_whisper_asr.py`（2026-08-13 检索）]
   - **标签剥离**：SenseVoice 输出可能带 `<|zh|><|NEUTRAL|><|Speech|>` 等元数据标签，FunASR 后端用 `re.sub(r"<\|.*?\|>", "", text)` 剥离（并处理带空格的异常形态）。[来源：一手源 `src/open_llm_vtuber/asr/fun_asr.py`（2026-08-13 检索）]
   - **工厂**：真实项目是 `ASRFactory.get_asr_system()` 的 if-else + 函数内延迟 import。[来源：一手源 `src/open_llm_vtuber/asr/asr_factory.py`（2026-08-13 检索）]

2. **我的实现和它差在哪？**
   - **相同**：接口抽象、16k 统一约定、多后端、工厂创建、设备降级、标签剥离
   - **你的改进**：注册表 + 装饰器代替 if-else（加后端不用改工厂）、延迟导入让 mock 测试不依赖真实后端、`conf.yaml` 零代码切换、标签剥离抽成可单测的独立函数
   - **本课简化**：只保留 `sense_voice` 一种 `model_type`（真实项目 8 种）；自动下载模型做成可选进阶；没有 VAD 分帧协同、说话人日志、热词（hotwords）等高级特性
