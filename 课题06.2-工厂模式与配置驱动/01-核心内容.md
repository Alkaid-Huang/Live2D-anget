## 3. 核心模型

### 3.1 第一性原理：为什么需要工厂？

**【推导】** 课题06.1 结束后，调用 VAD 的代码长这样：

```python
# 调用方直接 new
engine = SileroVADEngine(prob_threshold=0.5, db_threshold=-20, ...)
```

问题：
- 想换 `MockVAD` 测试？得改调用处：`engine = MockVAD(...)`
- 想加 `WebRTCVAD`？得改调用处
- 参数硬编码在调用处，改参数要改代码

**工厂模式** 解决：调用方不再直接 `new`，而是告诉工厂"我要什么类型的 VAD"，工厂负责创建：

```python
# 调用方只跟工厂打交道
engine = create_vad(vad_type="silero_vad", config=vad_config)
# 想换 MockVAD？改 vad_type="mock_vad" 就行，调用方代码不动
```

**【类比/解释】** 不用工厂像"你自己去菜市场买鸡杀鸡做菜"；用工厂像"跟厨师说你要什么菜，他帮你做好端上来"——你不需要知道怎么做。

### 3.2 第一性原理：为什么需要 Pydantic 配置校验？

**【推导】** 没有配置校验时代码长这样：

```python
engine = SileroVADEngine(prob_threshold=-0.5)  # 负数概率？运行时才发现
engine = SileroVADEngine(required_hits=0)       # 0次命中？逻辑错乱但不报错
```

问题：错误参数在**运行时**才暴露，可能藏很久。

**Pydantic** 解决：在配置加载时就校验，非法参数直接报错，不等到运行：

```python
class SileroVADConfig(BaseModel):
    prob_threshold: float = Field(ge=0.0, le=1.0)  # 限制 0~1
    required_hits: int = Field(gt=0)                 # 必须 > 0

# 加载时校验
config = SileroVADConfig(prob_threshold=-0.5)
# ❌ ValidationError: prob_threshold must be >= 0.0
```

**【事实】** Open-LLM-VTuber 用 Pydantic 的 `Field` 和 `model_validator` 进行配置校验。[$TRAE_REF](https://docs.pydantic.dev/latest/concepts/fields/) 其 `SileroVADConfig` 定义了 `orig_sr`、`target_sr`、`prob_threshold` 等字段。[来源：一手源 `config_manager/vad.py`（2026-08-03 检索）]

### 3.3 第一性原理：为什么需要 ServiceContext？

**【推导】** 没有 ServiceContext 时：

```python
# 全局变量散落各处
vad_engine = create_vad(...)
asr_engine = create_asr(...)   # 06.3 才有
tts_engine = create_tts(...)   # 08 才有
llm_engine = create_llm(...)   # 09 才有

# 调用方需要知道每个变量名
result = vad_engine.detect_speech(audio)
text = asr_engine.transcribe(result)
```

问题：
- 变量名冲突风险
- 组件间依赖关系不清晰
- 无法统一初始化、统一销毁

**ServiceContext** 解决：一个容器持有所有组件，调用方只跟容器打交道：

```python
ctx = ServiceContext(config)
ctx.init_vad()    # 内部调用 create_vad()
ctx.init_asr()    # 06.3 才加

# 调用方通过容器访问
result = ctx.vad_engine.detect_speech(audio)
```

**【事实】** Open-LLM-VTuber 的 `ServiceContext` 持有 `asr_engine`、`tts_engine`、`vad_engine`、`agent_engine` 等组件，通过 `init_vad(vad_config)` 方法调用 `VADFactory.get_vad_engine()` 创建实例。[来源：一手源 `service_context.py`（2026-08-03 检索）]

### 3.4 Open-LLM-VTuber 源码对照

#### 工厂：`vad_factory.py`

```python
# [一手源] Open-LLM-VTuber vad_factory.py（2026-08-03 检索）
class VADFactory:
    @staticmethod
    def get_vad_engine(engine_type, **kwargs) -> Type[VADInterface]:
        if engine_type is None:
            return None
        if engine_type == "silero_vad":
            from .silero import VADEngine as SileroVADEngine
            return SileroVADEngine(
                kwargs.get("orig_sr"),
                kwargs.get("target_sr"),
                kwargs.get("prob_threshold"),
                # ... 逐个取 kwargs
            )
```

> ⚠️ **参考答案的局限（你应超越）**：
> 1. 返回类型标注 `Type[VADInterface]` 是错的——返回的是**实例**不是**类型**
> 2. 参数用 `kwargs.get()` 逐个取，没有类型安全，传错参数不报错
> 3. `if engine_type == "silero_vad"` 用 if-else 链，加新后端要改工厂代码（可用字典+延迟导入改进）
> 4. 没有 CUDA→CPU 降级逻辑

#### 配置：`config_manager/vad.py`

```python
# [一手源] Open-LLM-VTuber config_manager/vad.py（2026-08-03 检索）
class SileroVADConfig(I18nMixin):
    orig_sr: int = Field(..., alias="orig_sr")
    target_sr: int = Field(..., alias="target_sr")
    prob_threshold: float = Field(..., alias="prob_threshold")
    db_threshold: int = Field(..., alias="db_threshold")  # 注意：int 类型
    required_hits: int = Field(..., alias="required_hits")
    required_misses: int = Field(..., alias="required_misses")
    smoothing_window: int = Field(..., alias="smoothing_window")

class VADConfig(I18nMixin):
    vad_model: Optional[Literal["silero_vad"]] = Field(None, alias="vad_model")
    silero_vad: Optional[SileroVADConfig] = Field(None, alias="silero_vad")
```

> ⚠️ **参考答案的局限**：
> 1. `db_threshold` 标注为 `int`，但实际可能是浮点数（课题06.1 用的 `-20.0`）
> 2. 没有 `Field(ge=0, le=1)` 等值域约束——`prob_threshold=-5` 不会报错
> 3. `I18nMixin` 是国际化描述，本课不需要

#### ServiceContext：`service_context.py`

```python
# [一手源] Open-LLM-VTuber service_context.py（2026-08-03 检索）
class ServiceContext:
    def __init__(self):
        self.vad_engine: VADInterface | None = None
        self.asr_engine: ASRInterface = None
        # ... 很多组件

    def init_vad(self, vad_config: VADConfig) -> None:
        if vad_config.vad_model is None:
            self.vad_engine = None
            return
        if not self.vad_engine or (self.character_config.vad_config != vad_config):
            self.vad_engine = VADFactory.get_vad_engine(
                vad_config.vad_model,
                **getattr(vad_config, vad_config.vad_model.lower()).model_dump(),
            )
            self.character_config.vad_config = vad_config
```

> ⚠️ **参考答案的局限**：
> 1. ServiceContext 太庞大——混合了 ASR/TTS/LLM/Live2D/MCP 等十几个组件
> 2. `getattr(vad_config, vad_config.vad_model.lower())` 动态取子配置——可读性差
> 3. `__init__` 全部设为 None，初始化散落在多个 init_xxx 方法中

## 4. 关键概念与例子

### 4.1 Pydantic V2 BaseModel —— 配置校验

```python
from pydantic import BaseModel, Field

class SileroVADConfig(BaseModel):
    """Silero VAD 配置（Pydantic 校验）"""
    prob_threshold: float = Field(default=0.5, ge=0.0, le=1.0)  # 0~1 之间
    db_threshold: float = Field(default=-20.0)                    # float32 用负数
    required_hits: int = Field(default=3, gt=0)                   # 必须 > 0
    required_misses: int = Field(default=24, gt=0)                # 必须 > 0
    smoothing_window: int = Field(default=5, gt=0)
    pre_buffer_size: int = Field(default=20, gt=0)
    window_size_samples: int = Field(default=512, gt=0)

# 合法配置
config = SileroVADConfig(prob_threshold=0.6)
print(config.prob_threshold)  # 0.6

# 非法配置 —— 加载时就报错，不等到运行
# SileroVADConfig(prob_threshold=-1.0)  # ❌ ValidationError
# SileroVADConfig(required_hits=0)      # ❌ ValidationError
```

**【事实】** Pydantic V2 的 `Field(ge=..., le=...)` 提供值域约束，`gt` 表示大于，`ge` 表示大于等于。非法值在 `BaseModel()` 构造时抛 `ValidationError`。[$TRAE_REF](https://docs.pydantic.dev/latest/concepts/fields/)

**关键方法速查表：**

| 方法/属性 | 作用 | 示例 |
|-----------|------|------|
| `Field(default=, ge=, le=, gt=)` | 定义字段默认值和约束 | `Field(default=0.5, ge=0.0, le=1.0)` |
| `model_validate(dict)` | 从字典创建（校验） | `SileroVADConfig.model_validate({"prob_threshold": 0.5})` |
| `model_dump()` | 转回字典 | `config.model_dump()` → `{"prob_threshold": 0.5, ...}` |
| `model_dump_json()` | 转回 JSON 字符串 | `config.model_dump_json()` |

### 4.2 工厂模式 —— create_vad()

```python
from typing import Dict, Type
from .vad_interface import VADInterface

# 注册表：后端名 → 类
_VAD_REGISTRY: Dict[str, Type[VADInterface]] = {}

def register_vad(name: str):
    """装饰器：注册 VAD 后端"""
    def decorator(cls):
        _VAD_REGISTRY[name] = cls
        return cls
    return decorator

@register_vad("silero_vad")
class SileroVADEngine(VADInterface):
    ...

@register_vad("mock_vad")
class MockVAD(VADInterface):
    ...

def create_vad(vad_type: str, **kwargs) -> VADInterface:
    """工厂函数：根据类型字符串创建 VAD 实例"""
    if vad_type not in _VAD_REGISTRY:
        raise ValueError(f"未知 VAD 类型: {vad_type}，可选: {list(_VAD_REGISTRY.keys())}")
    return _VAD_REGISTRY[vad_type](**kwargs)
```

**【关键】** 注册表模式比 if-else 链更好：加新后端只需 `@register_vad("new_type")`，不需要改工厂代码。这是**开闭原则**的体现。

**【事实】** Open-LLM-VTuber 的工厂用 `if engine_type == "silero_vad"` 链式判断。本课用注册表模式改进——加新后端不改工厂代码。[来源：一手源 `vad_factory.py`（2026-08-03 检索）]

### 4.3 ServiceContext —— 依赖注入容器

```python
class ServiceContext:
    """服务容器：统一管理所有组件"""

    def __init__(self, config: EchoConfig):
        self.config = config
        self.vad_engine: VADInterface | None = None

    def init_vad(self) -> None:
        """根据配置创建 VAD 引擎"""
        vad_type = self.config.vad_config.vad_type
        if vad_type == "none":
            self.vad_engine = None
            return
        vad_params = self.config.vad_config.get_vad_params()
        self.vad_engine = create_vad(vad_type, **vad_params)
```

**【关键】** ServiceContext 的核心思想：**调用方不直接创建组件，而是从容器获取**。这样组件的创建逻辑集中在一处，调用方只需要 `ctx.vad_engine`。

### 4.4 CUDA→CPU 降级

```python
import torch

def create_vad(vad_type: str, **kwargs) -> VADInterface:
    if vad_type == "silero_vad":
        try:
            return SileroVADEngine(**kwargs)
        except RuntimeError as e:
            if "cuda" in str(e).lower() or "device" in str(e).lower():
                # GPU 不可用，降级到 CPU
                print(f"⚠️ GPU 不可用，降级到 CPU: {e}")
                return SileroVADEngine(**kwargs)  # Silero 默认用 CPU
            raise  # 其他错误不吞
```

**【事实】** Open-LLM-VTuber 在 ASR 的 `provider` 配置中支持 `"cpu"` 和 `"cuda"`，但没有自动降级逻辑。本课要求你做到自动降级。[来源：一手源 `sherpa_onnx_asr.py` 的 `provider` 字段（2026-08-03 检索）]

## 5. 常见坑

### 坑 1：Pydantic V1 vs V2 API 差异

```python
# Pydantic V1（已废弃，别用）
class Config(BaseModel):
    prob: float = 0.5
    class Config:           # ❌ V1 的内部类配置方式
        min_value = 0

# Pydantic V2（正确）
class Config(BaseModel):
    prob: float = Field(default=0.5, ge=0.0)  # ✅ 用 Field 约束

# V2 的 model_validate 替代 V1 的 parse_obj
config = Config.model_validate({"prob": 0.5})  # ✅ V2
# config = Config.parse_obj({"prob": 0.5})    # ❌ V1
```

**【事实】** Pydantic V2 在 2023 年发布，API 有重大变化：`parse_obj` → `model_validate`，`Config` 内部类 → `model_config`。[$TRAE_REF](https://docs.pydantic.dev/latest/migration/)

### 坑 2：工厂忘了处理未知类型

```python
# ❌ 传了不认识的类型，静默返回 None
def create_vad(vad_type, **kwargs):
    if vad_type == "silero_vad":
        return SileroVADEngine(**kwargs)
    # 没有else！返回 None，调用方拿到的 None 还以为成功了

# ✅ 未知类型直接报错
def create_vad(vad_type, **kwargs):
    if vad_type not in _VAD_REGISTRY:
        raise ValueError(f"未知 VAD 类型: {vad_type}")
    return _VAD_REGISTRY[vad_type](**kwargs)
```

### 坑 3：ServiceContext 初始化顺序

```python
# ❌ VAD 还没初始化就用
ctx = ServiceContext(config)
result = ctx.vad_engine.detect_speech(audio)  # vad_engine 是 None！

# ✅ 先初始化再使用
ctx = ServiceContext(config)
ctx.init_vad()
result = ctx.vad_engine.detect_speech(audio)
```

### 坑 4：降级逻辑吞掉了不该吞的异常

```python
# ❌ 所有 RuntimeError 都降级，掩盖了真正的 bug
try:
    engine = SileroVADEngine(**kwargs)
except RuntimeError:
    engine = SileroVADEngine(**kwargs)  # 可能死循环或掩盖其他错误

# ✅ 只降级 GPU 相关错误
try:
    engine = SileroVADEngine(**kwargs)
except RuntimeError as e:
    if "cuda" in str(e).lower() or "device" in str(e).lower():
        engine = SileroVADEngine(**kwargs)
    else:
        raise  # 其他 RuntimeError 不吞
```

### 坑 5：conf.yaml 里的字段名和 Pydantic 模型不匹配

```python
# yaml 里写的
# vad_config:
#   vad_type: silero_vad
#   prob_threshold: 0.5

# Pydantic 模型里定义的
class VADConfig(BaseModel):
    vad_model: str       # ❌ yaml 里是 vad_type，模型里是 vad_model
    prob_threshold: float

# 加载时字段名不匹配，prob_threshold 会被忽略，用默认值
```

### 坑 6：注册表在导入时未填充

```python
# ❌ 工厂定义了注册表，但没有 import 后端模块
```

### 文件 5：conf.yaml（完整提供）

```yaml
# Echo 配置文件
# 修改 vad_type 即可切换 VAD 后端，无需改代码

vad_config:
  # 可选: "silero_vad"（真实现）, "mock_vad"（假实现）, "none"（禁用）
  vad_type: "silero_vad"

  silero:
    prob_threshold: 0.5
    db_threshold: -20.0       # float32 音频用负数（见课题06.1 坑7）
    required_hits: 3           # 连续命中 3 次确认开口（3×32ms≈0.1s）
    required_misses: 24        # 连续未命中 24 次确认说完（24×32ms≈0.77s）
    smoothing_window: 5        # 滑动窗口平滑
    pre_buffer_size: 20        # 预缓冲帧数（防切头）
    window_size_samples: 512   # silero-vad 每帧 512 采样点
```

"""

测试覆盖：

7. conf.yaml 加载

import pytest
import sys
import os

sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "src"))

from echo.config import SileroVADConfig, VADConfig, EchoConfig
from echo.vad.vad_interface import VADInterface
from echo.vad.vad_factory import create_vad, _VAD_REGISTRY
from echo.vad.mock_engine import MockVAD
from echo.service_context import ServiceContext


# ═══════════════════════════════════════════════════════════════
# 测试 1: Pydantic 配置校验 —— 合法值
# ═══════════════════════════════════════════════════════════════
def test_config_valid():
    """合法配置应该正常创建"""
    config = SileroVADConfig(prob_threshold=0.6, required_hits=5)
    assert config.prob_threshold == 0.6
    assert config.required_hits == 5
    assert config.db_threshold == -20.0  # 默认值


# ═══════════════════════════════════════════════════════════════
# 测试 2: Pydantic 配置校验 —— 非法值被拦截
# ═══════════════════════════════════════════════════════════════
def test_config_invalid_prob_threshold():
    """概率超出 0~1 应该报错"""
    from pydantic import ValidationError
    with pytest.raises(ValidationError):
        SileroVADConfig(prob_threshold=-0.1)
    with pytest.raises(ValidationError):
        SileroVADConfig(prob_threshold=1.5)


def test_config_invalid_required_hits():
    """required_hits <= 0 应该报错"""
    from pydantic import ValidationError
    with pytest.raises(ValidationError):
        SileroVADConfig(required_hits=0)
    with pytest.raises(ValidationError):
        SileroVADConfig(required_hits=-3)


# ═══════════════════════════════════════════════════════════════
# 测试 3: 工厂创建 MockVAD
# ═══════════════════════════════════════════════════════════════
def test_factory_create_mock():
    """工厂能创建 MockVAD"""
    engine = create_vad("mock_vad")
    assert isinstance(engine, VADInterface)
    assert isinstance(engine, MockVAD)


# ═══════════════════════════════════════════════════════════════
# 测试 4: 工厂拒绝未知类型
# ═══════════════════════════════════════════════════════════════
def test_factory_unknown_type():
    """传不认识的类型应该报 ValueError"""
    with pytest.raises(ValueError, match="未知 VAD 类型"):
        create_vad("nonexistent_vad")


# ═══════════════════════════════════════════════════════════════
# 测试 5: MockVAD 功能测试
# ═══════════════════════════════════════════════════════════════
def test_mock_vad_detect():
    """MockVAD 应该把输入原样吐出"""
    engine = create_vad("mock_vad")
    chunks = [(b"audio_np_placeholder", b"chunk1"), (b"audio_np_placeholder", b"chunk2")]
    results = list(engine.detect_speech(chunks))
    assert results == [b"chunk1", b"chunk2"]


# ═══════════════════════════════════════════════════════════════
# 测试 6: ServiceContext 依赖注入
# ═══════════════════════════════════════════════════════════════
def test_service_context_init_vad():
    """ServiceContext 能通过配置创建 VAD"""
    config = EchoConfig(
        vad_config=VADConfig(vad_type="mock_vad")
    )
    ctx = ServiceContext(config)
    assert ctx.vad_engine is None  # 初始化前是 None

    ctx.init_vad()
    assert ctx.vad_engine is not None
    assert isinstance(ctx.vad_engine, VADInterface)


# ═══════════════════════════════════════════════════════════════
# 测试 7: 配置驱动切换后端
# ═══════════════════════════════════════════════════════════════
def test_config_driven_switch():
    """改一行配置就能切换 VAD 后端"""
    # 用 mock_vad
    config_mock = EchoConfig(vad_config=VADConfig(vad_type="mock_vad"))
    ctx_mock = ServiceContext(config_mock)
    ctx_mock.init_vad()
    assert isinstance(ctx_mock.vad_engine, MockVAD)

    # 改成 none
    config_none = EchoConfig(vad_config=VADConfig(vad_type="none"))
    ctx_none = ServiceContext(config_none)
    ctx_none.init_vad()
    assert ctx_none.vad_engine is None


# ═══════════════════════════════════════════════════════════════
# 测试 8: conf.yaml 加载
# ═══════════════════════════════════════════════════════════════
def test_load_yaml_config():
    """从 conf.yaml 加载配置"""
    import yaml
    config_path = os.path.join(os.path.dirname(__file__), "..", "conf.yaml")
    with open(config_path, "r", encoding="utf-8") as f:
        raw = yaml.safe_load(f)

    config = EchoConfig.model_validate(raw)
    assert config.vad_config.vad_type == "silero_vad"
    assert config.vad_config.silero is not None
    assert config.vad_config.silero.prob_threshold == 0.5

| 审阅项 | 通过条件 |
|--------|---------|
| **接口解耦** | 工厂返回 `VADInterface`，不泄漏具体实现类型 |

2. **我的实现和它差在哪？**
   - 相同：工厂创建、配置校验、容器管理
   - **你的改进**：

     - Pydantic 加值域约束（`ge`/`le`/`gt`）
     - CUDA→CPU 自动降级
     - 返回类型标注正确（实例而非类型）

3. **参考答案的局限（供思考）**：
   - 工厂返回类型标注 `Type[VADInterface]` 是错的
   - 参数传递用 `kwargs.get()` 没有类型安全
   - ServiceContext 太庞大（十几个组件混在一起）
