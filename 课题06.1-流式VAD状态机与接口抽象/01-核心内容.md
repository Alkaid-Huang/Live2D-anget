## 3. 核心模型

### 3.1 第一性原理：为什么需要状态机？

**【推导】** 课题06 的离线 VAD 有个硬伤——它必须拿到**完整音频**才能调用 `get_speech_timestamps`。但实时对话中：
- 麦克风每 32ms 产生一小段音频（512 采样点）
- 用户随时可能开始说话、停顿、说完
- 我们不能"等用户说完 10 秒"才开始检测，那样延迟太大

所以需要一种"**来一段处理一段、随时能判断当前状态**"的机制——这就是**状态机**。它记住"之前是静音还是说话"，结合当前这一段的检测结果，决定要不要输出语音。

**【类比/解释】** 离线批处理像"看完一整部电影再写影评"；流式状态机像"边看边直播解说"——每来一帧，结合上下文判断"现在是开场、高潮还是结尾"。

### 3.2 三态状态机模型

对照 [一手源] Open-LLM-VTuber `src/open_llm_vtuber/vad/silero.py`（2026-07-27 检索）的 `State` 枚举：

```
                    连续命中 required_hits 次
        ┌──────────────────────────────────┐
        ▼                                  │
     ┌──────┐  连续命中     ┌──────┐         │
     │ IDLE │ ──────────→ │ACTIVE│         │
     │ 空闲  │              │ 说话中│         │
     └──────┘              └──┬───┘         │
        ▲                     │ 连续未命中   │
        │                     │ required_   │
        │ 输出语音段            │ misses 次   │
        │ (pre_buffer+bytes)   ▼            │
     ┌──────┐  连续命中     ┌────────┐       │
     │INACTIVE│ ←────────── │ 暂停态  │───────┘
     │ (静音) │ required_   └────────┘       (重新说话)
     └──────┘  misses 次
```

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| **IDLE** | 等待语音 | 启动 / INACTIVE 输出后 | 连续命中 `required_hits` 次 |
| **ACTIVE** | 正在说话 | IDLE/INACTIVE 连续命中 | 连续未命中 `required_misses` 次 |
| **INACTIVE** | 暂停（可能说完） | ACTIVE 连续未命中 | 继续未命中 → 输出并回 IDLE；或再次命中 → 回 ACTIVE |

**【事实】** Open-LLM-VTuber 默认 `required_hits=3`（3×32ms≈0.1s 确认开口）、`required_misses=24`（24×32ms≈0.77s 确认说完）。[来源：一手源 `silero.py`（2026-07-27 检索）]

> 💡 **参数含义（后续课题会复用）**：`required_hits` 防止咳嗽等短杂音误触发；`required_misses` 容忍换气停顿，避免把一句话切碎。这俩值在课题06.2 会进入 `conf.yaml`。

### 3.3 第一性原理：为什么需要双阈值？

**【推导】** 单阈值（只看 VAD 概率）的问题：
- 低阈值：装修噪音的"概率"也可能过线 → 误判
- 高阈值：小声说话漏检 → 漏判

**双阈值（概率 + 分贝）** 的抗噪逻辑：
- VAD 概率高 **且** 分贝高 → 才算说话（两个条件同时满足，更严格）
- 装修噪音：分贝高但"人声概率"低 → 被分贝放行但被概率拦截 ✅
- 小声说话：概率高但分贝低 → 被概率放行但被分贝拦截（这是代价，可调阈值权衡）

**【事实】** Open-LLM-VTuber 默认 `prob_threshold=0.4`、`db_threshold=60`，且对概率和分贝都做 `smoothing_window=5` 的滑动平均后再比较，避免单帧抖动误判。[来源：一手源 `silero.py`（2026-07-27 检索）]

### 3.4 第一性原理：为什么需要预缓冲？

**【推导】** 状态机在 IDLE 态等"连续命中 3 次才转 ACTIVE"。但这 3 帧（约 0.1s）的音频已经被判定为"语音"了——如果 IDLE 态没存它们，开口的第一个字（"你"）就被切掉了。

**预缓冲**：IDLE 态悄悄缓存最近 20 帧（约 0.64s），转 ACTIVE 时把它们拼到正式音频前面。

**【事实】** Open-LLM-VTuber 用 `deque(maxlen=20)` 实现滚动预缓冲，最终输出时 `pre_bytes = b"".join(self.pre_buffer)` 拼到正式音频前。[来源：一手源 `silero.py`（2026-07-27 检索）]

### 3.5 第一性原理：为什么需要抽象接口？

**【推导】** 课题06 的 `vad_detector.py` 直接 `from silero_vad import ...`，VAD 后端**写死**了。问题：
- 想换 WebRTC VAD？得改调用处代码
- 想加个 MockVAD 测试？得改调用处代码
- 调用方（管线）必须知道"具体用的是哪个 VAD"，耦合

**抽象接口** 解决：定义一个 `VADInterface` 契约（"任何 VAD 都必须有 `detect_speech` 方法"），调用方只依赖接口，不依赖具体实现。这样：
- 换后端：只需新写一个实现接口的类，调用方不动
- 测试：用 MockVAD（实现接口）替代真实模型

**【事实】** Open-LLM-VTuber 的 `VADInterface` 只定义一个抽象方法 `detect_speech`。[来源：一手源 `vad_interface.py`（2026-07-27 检索）]

```python
# Open-LLM-VTuber 的接口（参考答案）
from abc import ABC, abstractmethod

class VADInterface(ABC):
    @abstractmethod
    def detect_speech(self, audio_data: bytes):
        """检测语音活动，返回包含人声的音频字节序列"""
        pass
```

> ⚠️ **参考答案的局限（你应超越）**：Open-LLM-VTuber 的接口签名 `audio_data: bytes` 与实现 `detect_speech(audio_data: list[float])` 不一致；且**未用 `asyncio.to_thread` 包装同步推理**，会阻塞事件循环。本课要求你修正这两个问题——这就是"对照源码学习、超越源码"。

### 4.2 collections.deque —— 滑动窗口与预缓冲

```python
from collections import deque

# 滑动窗口（固定长度，新元素挤掉最老的）
probs = deque(maxlen=5)      # 最多存5个概率
probs.append(0.8)            # 加新值
probs.append(0.7)
avg = sum(probs) / len(probs)  # 滑动平均

# 预缓冲（滚动缓存最近20帧）
pre_buffer = deque(maxlen=20)
pre_buffer.append(b"chunk_bytes")  # 满了自动挤掉最老的
```

**关键方法速查表：**

| 方法 | 作用 | 参数 | 返回值 |
|------|------|------|--------|
| `deque(maxlen=N)` | 创建固定长度队列 | `maxlen`：最大容量 | `deque` 对象 |
| `d.append(x)` | 末尾添加，满了挤掉头部 | `x`：任意对象 | `None` |
| `len(d)` | 当前长度 | 无 | `int` |
| `sum(d)` | 求和（数字元素） | 无 | 数字 |
| `b"".join(d)` | 拼接字节序列 | `d`：字节的可迭代对象 | `bytes` |

### 4.3 abc.ABC —— 定义抽象基类

```python
from abc import ABC, abstractmethod

class VADInterface(ABC):           # 继承 ABC 才能用 abstractmethod
    @abstractmethod                # 标记为必须实现的方法
    def detect_speech(self, audio_chunks):
        """流式检测语音，返回语音段生成器"""
        pass

# 抽象类不能直接实例化
# vad = VADInterface()  # ❌ TypeError: 抽象类不能实例化

# 必须有子类实现所有抽象方法
class SileroVAD(VADInterface):
    def detect_speech(self, audio_chunks):
        for chunk in audio_chunks:
            ...
            yield speech_bytes
```

**【事实】** `abc.ABC` + `@abstractmethod` 是 Python 定义抽象基类的标准方式。子类必须实现所有 `@abstractmethod` 标记的方法，否则实例化时报 `TypeError`。[$TRAE_REF](https://docs.python.org/3/library/abc.html)

### 4.4 生成器 yield —— 流式输出

```python
def detect_speech(self, audio_chunks):
    """生成器：来一段处理一段，有完整语音段时 yield"""
    for chunk in audio_chunks:
        # 处理这一帧，更新状态机
        result = self.state_machine.process(chunk)
        if result is not None:
            yield result   # 吐出一个完整的语音段

# 调用方：用 for 循环消费生成器
for speech_segment in vad.detect_speech(audio_stream):
    print(f"得到一段语音: {len(speech_segment)} 字节")
```

**【关键】** 生成器 `yield` 的本质：**边算边吐**。调用方每 `for` 一次，生成器就跑到下一个 `yield`。这比"算完所有结果再返回列表"省内存，也支持实时流。

### 4.5 asyncio.to_thread —— 异步包装同步推理（超越参考答案）

```python
import asyncio

# VAD 推理是 CPU 密集型（torch），直接在 async 函数里调用会阻塞事件循环
async def async_detect_speech(self, audio_chunks):
    """把同步生成器包装成异步，不阻塞事件循环"""
    sync_gen = self.detect_speech(audio_chunks)  # 同步生成器
    while True:
        # 用 to_thread 取下一个值，不阻塞
        try:
            chunk = await asyncio.to_thread(next, sync_gen)
        except StopIteration:
            break
        yield chunk
```

> 💡 **为什么这是本课的"超越点"**：Open-LLM-VTuber 的 VAD 模块**没有**用 `asyncio.to_thread`，同步 torch 推理会阻塞事件循环（违反 AGENTS.md 工程化审阅清单）。本课要求你做到——这是"对照源码学习，不是照抄源码"的体现。

### 4.6 分贝计算（RMS）

```python
import numpy as np

@staticmethod
def calculate_db(audio_np: np.ndarray) -> float:
    """计算音频的分贝值（RMS 法）"""
    rms = np.sqrt(np.mean(audio_np ** 2))
    return 20 * np.log10(rms + 1e-7)  # +1e-7 防止 log(0)
```

**【事实】** Open-LLM-VTuber 用 `20 * log10(rms + 1e-7)` 计算分贝，`+1e-7` 防止静音时 `log10(0)` 报错。[来源：一手源 `silero.py`（2026-07-27 检索）]

## 5. 常见坑

### 坑 1：生成器不调用就不执行

```python
def detect_speech(self, chunks):
    for c in chunks:
        yield process(c)   # 定义了生成器

# ❌ 只定义不消费，里面代码根本没跑
vad.detect_speech(audio)  # 返回生成器对象，没执行

# ✅ 必须 for 消费
for seg in vad.detect_speech(audio):
    print(seg)
```

### 坑 2：deque 的 maxlen 不是"初始长度"

```python
d = deque(maxlen=5)   # 最多存5个，但现在是空的
print(len(d))         # 0，不是 5
# append 第6个时，第1个被自动挤掉
```

### 坑 3：抽象方法没实现就实例化

```python
class MyVAD(VADInterface):
    pass  # ❌ 没实现 detect_speech

MyVAD()  # TypeError: Can't instantiate abstract class MyVAD
```

### 坑 4：在 async 函数里直接跑 CPU 密集任务

```python
async def handle(audio):
    result = model(audio)   # ❌ torch 推理阻塞事件循环，其他协程卡死
    # ✅ await asyncio.to_thread(model, audio)
```

### 坑 5：状态机忘了重置计数器

```python
# IDLE → ACTIVE 后，hit_count 必须清零
# 否则下次判断会带上历史命中数，状态转换逻辑错乱
```

### 坑 6：预缓冲拼错顺序

```python
# ❌ 先 bytes 后 pre（顺序反了，开头被推到后面）
yield self.bytes_buffer + pre_bytes

# ✅ 先 pre（开头）后 bytes（正文）
yield pre_bytes + self.bytes_buffer
```

### 坑 7：db_threshold 必须与音频数值范围匹配

```python
# float32 音频（值域 -1.0~1.0）的分贝范围约 -140~0：
#   calculate_db(0.5) ≈ -6dB    calculate_db(0.0) ≈ -140dB
# int16 音频（值域 -32768~32767）的分贝范围约 0~90

# Open-LLM-VTuber 源码默认 db_threshold=60，是因为它的音频走 int16 范围
# 本课用 float32，所以阈值要用负数（如 -20），否则永远不命中！

sm = StateMachine(db_threshold=60)   # ❌ float32 下分贝最高才 0，永远到不了 60
sm = StateMachine(db_threshold=-20)  # ✅ loud(-6dB) 命中，silence(-140dB) 不命中
```

### 文件 1：vad_interface.py（完整提供，直接保存）

```python
"""
VAD 抽象接口 —— 所有 VAD 后端的统一契约
对照 Open-LLM-VTuber 的 vad_interface.py（2026-07-27 检索）
"""
from abc import ABC, abstractmethod
from typing import Generator


class VADInterface(ABC):
    """VAD 抽象基类：定义所有 VAD 后端必须实现的契约"""

    @abstractmethod
    def detect_speech(self, audio_chunks) -> Generator[bytes, None, None]:
        """
        流式检测语音段。

        参数:
            audio_chunks: 可迭代的音频块，每块是 (prob, audio_np, chunk_bytes)
                          prob: 该块是语音的概率 (float)
                          audio_np: numpy 数组 (用于算分贝)
```

```python
"""
流式 VAD 状态机
对照 Open-LLM-VTuber silero.py 的 StateMachine（2026-07-27 检索）

三态：IDLE → ACTIVE → INACTIVE → (输出) → IDLE
双阈值：概率阈值 + 分贝阈值（滑动窗口平滑后比较）
预缓冲：IDLE 态缓存最近 pre_buffer_size 帧，防止开口第一个字被切掉
"""
from enum import Enum
from collections import deque
import numpy as np


class State(Enum):
    """VAD 三态"""
    IDLE = 1       # 空闲，等待语音
    ACTIVE = 2     # 检测到语音
    INACTIVE = 3   # 语音暂停（可能说完）


class StateMachine:
    """流式 VAD 状态机"""

    def __init__(
        self,
        prob_threshold: float = 0.5,      # 语音概率阈值
        db_threshold: float = -20.0,       # 分贝阈值（float32 用负数，见坑7）
        required_hits: int = 3,           # 连续命中几次确认"开始说话"
        required_misses: int = 24,        # 连续未命中几次确认"说完了"
        smoothing_window: int = 5,        # 滑动窗口大小（平滑概率和分贝）
        pre_buffer_size: int = 20,       # 预缓冲帧数（防切头）
    ):
        self.state = State.IDLE

        # 阈值参数
        self.prob_threshold = prob_threshold
        self.db_threshold = db_threshold
        self.required_hits = required_hits
        self.required_misses = required_misses

        # 滑动窗口（deque 满了自动挤掉最老的）
        self.probs = deque(maxlen=smoothing_window)
        self.dbs = deque(maxlen=smoothing_window)

        # 预缓冲（IDLE 态悄悄存，转 ACTIVE 时拼到前面）

    def _is_hit(self, prob: float, db: float) -> bool:

        self.dbs.append(db)

        smoothed_db = sum(self.dbs) / len(self.dbs)
        return smoothed_prob >= self.prob_threshold and smoothed_db >= self.db_threshold

        处理一帧，返回完整语音段（bytes）或 None。

        这是状态机核心：根据当前状态 + 是否命中，更新状态并决定是否输出。
        返回 bytes 表示"这段语音完整了，吐出去"；返回 None 表示"继续累积"。

        参数:
            prob: 该帧是语音的概率 (0.0~1.0)
            audio_np: 该帧的 numpy 数组（算分贝用）

        """

            #         - hit_count = 0
            #         - return None（继续累积，不打断）
            # 2. 若未命中: miss_count += 1
```

他们两个最本质的区别在于：

## 附录：源码对照学习指引

学完本课后，回答以下问题（对照 Open-LLM-VTuber 源码）：

1. **Open-LLM-VTuber 是怎么做的？** 它的 `StateMachine` 在 `silero.py` 里，用 `IDLE/ACTIVE/INACTIVE` 三态 + 双阈值 + 滑动窗口平滑 + 预缓冲 `deque(maxlen=20)` + 生成器 `yield` 流式输出。[来源：一手源（2026-07-27 检索）]

2. **我的实现和它差在哪？**
   - 相同：三态、双阈值、预缓冲、生成器
   - **你的改进**：用 `asyncio.to_thread` 包装异步（参考答案没做）
   - **参考答案的另一个细节**：它还 `yield` 了 `<|PAUSE|>` / `<|RESUME|>` 标记（教学版省略，可作加分项）

3. **参考答案的局限（供思考）**：
   - 接口签名 `audio_data: bytes` 与实现 `list[float]` 不一致
   - 工厂返回类型标注 `Type[VADInterface]` 写错（应为实例类型）
   - 存在两个同名 `SileroVADConfig`（config 层 vs 运行时层）
