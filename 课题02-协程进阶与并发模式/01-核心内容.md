## 3. 核心模型：生产者-消费者管线

**【类比/解释】** 把 Echo 的语音管线想象成一条流水线：

```
麦克风采集 ──→ [音频队列] ──→ Whisper 识别 ──→ [文字队列] ──→ LLM 生成 ──→ [回复队列] ──→ TTS 播放
  (生产者)       (缓冲区)      (消费者/生产者)     (缓冲区)       (消费者/生产者)    (缓冲区)       (消费者)
```

每个环节的产出速度不同。麦克风一秒钟能采集 16000 个采样点，但 Whisper 处理 1 秒音频可能需要 0.3 秒。如果中间没有缓冲区（队列），麦克风就必须等 Whisper 处理完才能继续采集，整个过程就串行化了。

**队列就是那个"缓冲地带"**——生产者只管往里扔，消费者只管从里面取，互不阻塞。

```
┌──────────┐     put()     ┌──────────────┐     get()     ┌──────────┐
│  生产者A  │ ───────────→ │  asyncio.    │ ───────────→ │  消费者B  │
│ (快速产出) │              │   Queue(10)  │              │ (慢速处理) │
└──────────┘              │  最多存10条   │              └──────────┘
                           └──────────────┘
                          如果队列满了 →
                          put() 会等待（背压）
                          生产者被"刹车"
```

**【事实】** `asyncio.Queue(maxsize=N)` 是有界队列。当队列满时，`put()` 会阻塞（await）直到有空位；当队列空时，`get()` 会阻塞直到有新数据。这就是**背压（backpressure）**——用队列容量限制上游，防止内存无限增长。

## 4. 关键概念与例子

### 4.1 `asyncio.Queue` — 协程间安全的数据通道

```python
import asyncio

async def producer(queue: asyncio.Queue):
    """生产者：每秒产生一条数据"""
    for i in range(5):
        await asyncio.sleep(1)  # 模拟生产耗时
        item = f"数据-{i}"
        await queue.put(item)   # 放入队列，如果满了就等待
        print(f"  生产: {item}  (队列大小: {queue.qsize()})")

async def consumer(queue: asyncio.Queue):
    """消费者：每 0.3 秒处理一条数据"""
    while True:
        item = await queue.get()  # 从队列取出，如果空了就等待
        print(f"        消费: {item}")
        await asyncio.sleep(0.3)  # 模拟处理耗时
        queue.task_done()         # 标记这条数据已处理完毕

async def main():
    queue = asyncio.Queue(maxsize=3)  # 最多缓冲 3 条
    # 同时启动生产者和消费者
    prod = asyncio.create_task(producer(queue))
    cons = asyncio.create_task(consumer(queue))
    
    await prod  # 等生产者完成
    await queue.join()  # 等队列中所有数据都被处理完
    cons.cancel()  # 取消消费者

asyncio.run(main())
```

**关键点**：
- `queue.qsize()` 返回当前队列大小（近似值，仅用于调试）
- `queue.task_done()` 告诉队列"这条数据处理完了"
- `queue.join()` 阻塞直到所有 `task_done()` 被调用

### 4.2 背压（Backpressure）— 用队列大小限制上游

```python
async def fast_producer(queue: asyncio.Queue):
    for i in range(100):
        await queue.put(f"数据-{i}")
        # 如果队列满了（maxsize），这里会自动等待
        # 相当于给生产者"踩刹车"
        print(f"生产了: {i}")

# queue = asyncio.Queue(maxsize=5)  ← 背压就在这里
# 生产者最多领先消费者 5 条数据，不会无限积压
```

**【类比/解释】** 背压就像餐厅厨房的"出菜口"——只能放 5 盘菜。如果服务员（消费者）来不及端，厨师（生产者）出菜口满了就得停下来等，而不是无限做菜堆满整个厨房。

### 4.3 `asyncio.wait_for` — 超时控制

```python
async def slow_task():
    await asyncio.sleep(10)
    return "完成"

async def main():
    try:
        result = await asyncio.wait_for(slow_task(), timeout=3.0)
        print(result)
    except asyncio.TimeoutError:
        print("任务超时了！3 秒内没完成")
```

**【事实】** `wait_for` 会在超时后抛出 `TimeoutError`，同时**自动取消**被包装的协程。这是 Echo 中处理"LLM 推理卡住"的关键机制。

### 4.4 协程取消 — 优雅停机

```python
import asyncio

async def worker(name: str):
    try:
        while True:
            print(f"{name} 工作中...")
            await asyncio.sleep(1)
    except asyncio.CancelledError:
        # 被取消时执行清理
        print(f"{name} 正在清理资源...")
        await asyncio.sleep(0.1)  # 模拟清理
        print(f"{name} 已安全退出")
        raise  # 重要：重新抛出，让调用者知道被取消了

async def main():
    task = asyncio.create_task(worker("Worker-1"))
    await asyncio.sleep(3)     # 让它跑 3 秒
    task.cancel()              # 发送取消信号
    try:
        await task             # 等待取消完成
    except asyncio.CancelledError:
        print("Worker-1 已被取消")

asyncio.run(main())
```

**输出**：
```
Worker-1 工作中...
Worker-1 工作中...
Worker-1 工作中...
Worker-1 正在清理资源...
Worker-1 已安全退出
Worker-1 已被取消
```

**【事实】** 关键规则：
- `task.cancel()` 只是**发出信号**，协程必须自己在 `await` 点响应
- 被取消的协程抛出 `CancelledError`，你可以用 `try/finally` 做清理
- **清理完后必须 `raise`**，否则任务会"吞掉"取消信号，继续运行

### 4.5 `asyncio.Event` — 协程间的信号灯

```python
async def waiter(event: asyncio.Event, name: str):
    print(f"{name} 在等待信号...")
    await event.wait()  # 阻塞直到 event.set() 被调用
    print(f"{name} 收到信号，开始工作！")

async def main():
    event = asyncio.Event()
    tasks = [asyncio.create_task(waiter(event, f"Worker-{i}")) for i in range(3)]
    await asyncio.sleep(2)
    print("发送信号！")
    event.set()  # 所有等待者同时收到信号
    await asyncio.gather(*tasks)

asyncio.run(main())
```

## 5. 常见坑

### 坑 1：消费者死循环忘记取消

```python
async def consumer(queue):
    while True:  # ❌ 永远停不下来
        item = await queue.get()
        ...
```

消费者通常需要外部 `cancel()` 来停止，或者用一个哨兵值（如 `None`）来通知退出。

### 坑 2：`task_done()` 调用次数不匹配

```python
# 生产者 put 了 5 次，但消费者只调了 3 次 task_done()
# queue.join() 会永远等下去！
```

### 坑 3：取消后忘记 `raise`

```python
except asyncio.CancelledError:
    print("清理中...")
    # ❌ 忘记 raise！任务会静默继续运行
```

### 坑 4：在 `finally` 中做耗时操作

```python
try:
    await do_work()
finally:
    await asyncio.sleep(5)  # ❌ 取消后清理不能太久！可能被强制终止
```
