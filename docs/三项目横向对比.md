## 二、三家其实是三种物种

### Open-LLM-VTuber —— "品类定义者"

**做什么**：让 LLM 通过免提语音与 Live2D 形象对话，全平台、可离线。
亮点在**覆盖广度与用户生态**：Web 版 + 桌面客户端（含**透明桌面宠物模式**）、多语言 README（英日韩中）、
Docker 镜像、MCP 集成、角色定制文档、活跃社区（QQ 群 / Zulip / Discord）。

**最强的地方**：生态与影响力；"能装能跑能分享"的完成度。
**弱的地方**：v1 目前处于维护状态（四个月未推送功能更新，官方在筹备 v2.0 重写），
Python 单体代码库、扩展要读源码改配置。

### Prometheus Avatar —— "给开发者的乐高"

**做什么**：把"驱动头像"抽成 SDK——`npm install @prometheusavatar/core`，
5 行代码让任意 LLM 输出变成带**口型同步 + 情绪表情**的角色。

从它生成的 API 文档能看到非常干净的模块划分：

| 模块 | 职责 |
|------|------|
| `PrometheusAvatar` / `createAvatar()` | 门面：初始化模型、TTS、口型、情绪 |
| `Live2DRenderer` | 渲染 Cubism 2 & 4 模型，自动缩放居中 |
| `LipSyncEngine` | 音频 → 口型帧（`LipSyncFrame`） |
| `EmotionAnalyzer` | 文本 → 情绪（`EmotionResult`） |
| `AssetManager` | 模型/皮肤资源与 `AssetManifest` |
| `ILLMProvider` / `ITTSEngine` | 可插拔的模型与语音接口 |
| `AvatarEventMap` | 事件驱动（状态变化对外广播） |

分发方式也很"开发者友好"：npm 包 + **MCP server**（任何 MCP 客户端都能获得头像）+ Agent Skill 插件。

**最强的地方**：接入体验与前端工程化；**MIT 许可**最友好；
实时语音走 Gemini Live（WebSocket 流式，自称 ~200ms，内置 VAD 与打断）；
还带 **VTuber 模式**（摄像头人脸跟踪驱动头部动作）与 Marketplace（皮肤/声音/角色的交易生态）。
**弱的地方**：很新（16★，3 月建仓），本身不是完整产品，长期维护与生态仍在建立中。

### D_sakiko —— "把 Agent 做深"

**做什么**：桌面数字生命应用，主线是 **Agent 深度**而不是前端体验。

| 能力 | 实现 |
|------|------|
| 编排 | 自研 ReAct 引擎 + ToolRegistry + **工具沙箱，异常 traceback 转 prompt 让模型自纠错** |
| 知识 | **Qdrant 向量 + BM25 稀疏双路召回 → RRF 融合 → Reranker 精排**；用作品时间线构建"世界书"防 OOC |
| 记忆 | 短期滑动窗口 + **异步反思**抽取关键事件向量化落盘，阈值触发召回 |
| 情绪 | 独立模块，**BERT-base-Chinese 微调 7 分类**（happiness/sadness/anger/disgust/like/surprise/fear） |
| 语音 | **GPT-SoVITS 语音克隆**（角色用自己的声线） |
| Live2D | 桌面 `live2d-py + PyQt5`；另有 React + Cubism Core 5 的 WebUI；后端有**呈现契约模块** |
| 产品化 | 一键安装包（Win/macOS）、网盘分发、更新器/修复器（带回滚）、对话备份/分叉、角色管理、模型下载器 |

**最强的地方**：Agent 深度与产品完整度；文档治理也最成熟（`AGENTS.md` + **`CONTEXT.md` 领域术语表**）。
**弱的地方**：**GPL-3.0**（代码不可抄）、体量大、桌面端技术栈偏重（PyQt5 + 本地 TTS/克隆）。

## 三、分维度"谁更优秀"

| 维度 | 更优秀者 | 依据 |
|------|---------|------|
| 生态与用户规模 | **Open-LLM-VTuber** | 13.7k★、1639 fork、多语言文档、Docker、MCP、社区渠道齐全 |
| 开发者接入体验 | **Prometheus** | MIT + npm + 5 行代码 + TypeDoc API + MCP server + Skill 分发 |
| 模块划分清晰度 | **Prometheus** | Renderer / LipSync / Emotion / Asset / TTS 全部接口化 + 事件表 |
| Agent 深度（工具/知识/记忆） | **D_sakiko** | ReAct + 工具沙箱自纠错 + RAG 四段式 + 反思记忆 |
| 人设一致性 | **D_sakiko** | "世界书"知识库 + 角色描述文件 + 术语表 |
| 情绪识别可靠性 | **D_sakiko** | 专用 BERT 分类模型（可评测），而非让 LLM 自评 |
| 声音个性化 | **D_sakiko** | GPT-SoVITS 语音克隆（角色声线） |
| 实时语音延迟设计 | **Prometheus** | Gemini Live WebSocket 流式（~200ms）+ 内置 VAD/打断 |
| 桌面端体验 | **Open-LLM-VTuber / D_sakiko** | 前者桌面宠物透明模式；后者原生 PyQt 窗口 |
| 工程与分发成熟度 | **D_sakiko**（应用）/ **Open-LLM-VTuber**（镜像与文档） | 更新器/修复器/备份/一键包 vs Docker/文档站 |
| 许可友好度 | **Prometheus（MIT）** | 其次 OLM-V（自定义，需读条款），最严 D_sakiko（GPL-3.0） |
| 活跃度（当下） | **D_sakiko** | 昨天仍有推送；OLM-V 近四个月无功能更新 |
| 产品质量口碑 | **Open-LLM-VTuber** | 星标与 issue 量级说明被大规模真实使用 |

## 四、对 Echo 的启示（对应我们的 M3 / M4）

1. **呈现层学 Prometheus**：把"驱动头像"做成独立模块而不是塞进业务代码——
   `Renderer` / `LipSyncEngine` / `EmotionAnalyzer` / `AssetManager` + 事件表。
   我们已有事件流（thinking/tool_call/speech/emotion），缺的就是这层契约化拆分。
2. **命名与状态建模学 D_sakiko**：定义标准动作组 id（`IDLE` / `text_generating` / 情绪组）、
   方向变体回退规则、以及呈现契约字段（版本 / 解析状态 / 布局 / 能力 / 错误码）。
3. **产品形态学 Open-LLM-VTuber**：Web + 桌面双端是成熟路线；我们先做 Web，桌面作为第二实现。
4. **许可红线**：Prometheus 是 MIT（可参考，但仍应有自己的实现与出处说明）；
   D_sakiko 是 GPL-3.0（**只看思路，不抄代码**）；OLM-V 是自定义许可，需读原文。
5. **差异化定位**：三家都不以"可验证的工程质量"为卖点——
   Echo 的标签应该是 **可测（52 个 mock 测试）+ 可观测（事件流与延迟基准）+ 契约清晰（接口/呈现/配置）**。
