# Echo 项目 · 面试拷打手册

> 用法：面试前把每题的"答题骨架"用自己的话说一遍，别背稿。
> 每道题的答案都必须能落到本项目**真实代码或真实经历**上。

---

## 0. 一分钟项目介绍（背熟）

**30 秒电梯版**

> Echo 是一个本地优先的桌面 AI 伴侣，参考开源项目 Open-LLM-VTuber 的架构思路自己实现。
> 它把"人说话"到"角色开口回应"做成一条实时链路：VAD 断句 → ASR 转写 → LLM 生成 → TTS 合成 → 播放，
> 并且支持说话打断。四个组件都用"抽象接口 + 工厂 + 配置 + 依赖注入"组织，改一行配置就能换后端。

**2 分钟技术版**（在电梯版后面补这几句）

> 我做的取舍是：不追求功能堆叠，而是把工程性做扎实。
> 比如四个组件都有 mock 实现，所以一条命令就能在没有任何模型、网络、声卡的机器上跑通整条管线并跑测试，
> 现在 36 个测试全绿；推理用 `asyncio.to_thread` 包装不阻塞事件循环；
> 我还真踩过一个坑——`device="auto"` 选了 CUDA 但机器缺 cuBLAS，程序在推理时才崩，
> 最后做成运行期检测异常自动降级 CPU，并补了防回归测试。

## 1. 项目背景类（面试官必问，先声夺人）

**Q1：这个项目是做什么的？为什么做它？**

答题骨架：目标（桌面 AI 伴侣）→ 参考对象（Open-LLM-VTuber）→ 你自己的切入口（先做实时语音内核，再挂 Live2D 形象）。
不要只说"我想练手"，要说"我想验证一个真实系统里最难的部分：实时链路与多组件协作"。

**Q2：和 Open-LLM-VTuber 的关系是什么？抄的还是自己写的？**

答题骨架：**参考架构思路，代码自己实现**。具体差异要能说出来：
- 它的 ASR 工厂是 if-else + 函数内延迟 import；我用注册表 + 装饰器，加后端不用改工厂代码
- 它的 SenseVoice 输出用 `re.sub` 剥标签，我抽成独立函数并加了单测
- 我的 `ServiceContext` 统一管理四类组件，配置用 Pydantic 做强校验（非法 provider 直接拦下）

**Q3：现在的完成度？能演示吗？**

答题骨架：能演示三条命令——`--mode check`（组件就绪）、`--mode tts`（出声）、`--mode asr`（转写）。
诚实说明：LLM 目前可切 Ollama 本地模型；Live2D 形象是下一里程碑。

## 2. 架构类

**Q4：画一下整体架构。**

白板顺序：麦克风 → VAD（三态状态机）→ ASR → LLM → TTS → 播放；旁挂 `ServiceContext` 和各组件的工厂。
要点：**每个组件只依赖接口**，管线不认识具体实现。

**Q5：为什么要接口 + 工厂 + 配置？直接 new 不行吗？**

答题骨架：三个真实收益——
1. 换后端零改动：改 `conf.yaml` 一行；
2. 可测试：mock 后端让整条管线能在 CI 里跑；
3. 可扩展：加一个 Whisper.cpp 后端 = 新文件 + 一行装饰器。

**Q6：依赖注入解决了什么问题？**

答题骨架：组件创建集中在一处（`ServiceContext`），没有全局变量；测试时可以整体替换成 mock；
管线只拿接口，生命周期清晰（启动时 `init_all()`）。

**Q7：如果让你加一个"通义千问 API"后端，要改哪些文件？**

答题骨架：新增 `llm/qwen_llm.py` 一个文件 + `@register_llm("qwen")`，`conf.yaml` 加一段配置。
**工厂和管线一行不改**——这就是开闭原则的验证方式。

## 3. 技术选型类（"为什么不用 X"高频）

**Q8：VAD 为什么选 silero？双阈值是怎么回事？**

答题骨架：silero 是轻量 ONNX 模型、CPU 也能实时跑；
双阈值 = 语音概率 + 能量分贝同时达标才算"在说话"，比单阈值抗噪；
再加 `required_hits/required_misses` 防抖，和 `pre_buffer_size` 预缓冲防止开口第一个字被切掉。

**Q9：ASR 为什么用 faster-whisper？small + int8 的依据？**

答题骨架：faster-whisper 是 Whisper 的 CTranslate2 重实现，同精度下更快更省显存；
实测 5 秒音频 CPU int8 约 1.5 秒；small 是在 8GB 显存与中文效果之间的平衡点。

**Q10：TTS 为什么用 edge-tts？要完全离线怎么办？**

答题骨架：edge-tts 免费、中文自然、接入成本最低；
离线替代是 sherpa-onnx 的本地 TTS（界面已按同样模式预留），代价是音质与体积。
**能说出"我为什么先选它，以及什么条件下我会换掉它"，比说出"它最好"更打动面试官。**

**Q11：LLM 为什么用 Ollama？和 vLLM、LangChain 什么关系？**

答题骨架：Ollama 解决"本地跑模型 + 模型管理"，vLLM 解决"高并发吞吐"，两者不冲突；
LangChain 是编排框架，我的链路只有一步调用，引入它属于过度设计——**这是加分回答**。

## 4. 并发与性能类（区分"用过"和"懂"）

**Q12：在 asyncio 事件循环里跑模型推理会怎样？你怎么处理？**

答题骨架：CPU 推理是同步阻塞调用，会卡住整个事件循环，导致音频回调堆积、打断失灵；
我用 `asyncio.to_thread` 把推理扔进线程池，接口给默认实现，后端不用重写。

**Q13：`to_thread` 有什么坑？**

答题骨架：默认线程池大小有限（约 CPU 核数），高并发时会排队；
线程池里的任务**取消不掉**（`await` 被取消不等于底层推理停止）；
所以真正的"打断"要用停止信号 + 状态标记，而不是指望 cancel 掉推理。

**Q14：打断是怎么实现的？**

答题骨架：播放放在独立线程，`threading.Event` 作为停止开关；
主循环播放期间继续读麦克风，VAD 一旦 `is_speaking()` 变 True 就 `set()` 事件，播放线程在写音频块的间隙退出。
然后新语音继续走完整链路。实测打断响应取决于音频块大小（512 采样 ≈ 32ms）。

**Q15：端到端延迟怎么拆？现在多少？瓶颈在哪？**

答题骨架：`VAD 收尾(约 0.8s 静音判定) + ASR(1.5s/5s 音频) + LLM(取决于模型) + TTS(1~2s) + 播放启动`。
现在最大的两处：**LLM 非流式**（要等整句生成）和 **TTS 全句合成**（要等整段音频）。
下一步优化方向：LLM 流式 + 按标点分句送 TTS，先出声再补全——这就是"首字延迟"思路。

## 5. 故障与稳定性类

**Q16：讲一个你实际遇到的 bug。**

答题骨架（真实案例）：`device="auto"` → 选 CUDA → 机器缺 cuBLAS → 推理时抛 `cublas64_12.dll is not found`。
排查：模型能加载说明不是文件问题，报错在 `encode` 说明是算子问题，错误信息直指缺库。
修复：捕获设备类异常后自动用 CPU + int8 重建模型重试；顺手把默认配置改成 `cpu`，并补一条防回归测试。
**升华一句**："自动选设备"这类智能默认值，失败点往往在第一次真正计算时，所以回退逻辑必须放在能够兜住的地方。

**Q17：用户没装依赖 / 模型文件缺失会怎样？**

答题骨架：真实后端延迟导入，缺依赖抛出带安装命令的 `ImportError`，不影响 mock 链路；
模型缺失抛 `FileNotFoundError` 并给下载指引，而不是等到推理时报奇怪错误。

**Q18：对话历史越来越长怎么办？**

答题骨架：按轮数裁剪（`max_history_turns`），落 JSON 持久化；将来要做的是摘要压缩 + 向量检索。
顺带说出它的局限：**裁剪是"丢最旧的"，对长期记忆不友好**。

## 6. 工程化与测试类

**Q19：测试怎么组织的？为什么不依赖真实模型？**

答题骨架：36 个用例覆盖接口契约、工厂、配置校验、容器注入、标签剥离、管线端到端与降级防回归；
全部用 mock 后端 + 可注入的假麦克风/假播放器，所以**能在任何机器、任何 CI 上跑**，不依赖网络和声卡。

**Q20：mock 算不算造假？**

答题骨架：不算。mock 是**契约测试**——它验证的是"接口与编排正确"；
真实模型的效果验证是另一层（我用真实录音跑过 ASR、用真实文本跑过 TTS，并记录了耗时）。
两层测试职责不同，缺一不可。

## 7. 不足与反思（一定要主动说）

**Q21：这个项目有什么不足？**

答题骨架（按"知道 + 有应对"的方式说）：
1. **没有 AEC 回声消除**：外放时可能自己打断自己，当前建议戴耳机，方案是 WebRTC AEC 或半双工；
2. **非流式**：首字延迟高，计划做 LLM 流式 + TTS 分句；
3. **Live2D 形象未接入**：这是下一里程碑，链路侧已经预留"播放状态/情感标签"输出；
4. **没有端到端压测与监控**：目前只有单点延迟记录。

**Q22：如果重做一次，你会改什么？**

答题骨架：先定义接口契约与 mock，再写实现（这次的顺序是对的，要继续保持）；
更早引入端到端延迟指标，让每次改动都能量化；
VAD/ASR 从一开始就用"块级处理"接口，避免后来为了打断再拆 `process_block`。

## 8. 深水区追问（面试官用来分辨真假项目）

| 追问 | 答题要点 |
|------|---------|
| 为什么整条链路统一 16kHz？ | 语音模型（VAD/Whisper）都在 16k 上训练；统一约定比每次传采样率更安全，接口用常量固定 |
| 采样率不一致会怎样？ | 听感变调、识别率暴跌；排查方法是先量文件头采样率，再检查重采样点 |
| 预缓冲 20 帧是多少秒？ | 512 采样/帧、16kHz → 32ms/帧，20 帧约 0.64 秒 |
| 为什么 `required_misses=24`？ | 24×32ms≈0.77s，即"停顿约 0.8 秒才算说完"，是响应速度与断句准确率的折中 |
| 线程池里的推理能取消吗？ | 不能，cancel 只取消等待；要真正停止必须靠停止标志或丢弃结果 |
| 为什么不直接用 WebRTC？ | 语音通话栈解决传输与回声，本项目当前是单机闭环；引入它的收益在"远程实时"，不在当前阶段 |
| 怎么衡量打断体验？ | 从用户开口到播放停止的时间，目标 <300ms；当前粒度受音频块大小限制 |
