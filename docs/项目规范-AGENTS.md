# Echo 项目开发规范（AGENTS.md）

> 本文件面向参与本仓库的开发者与 AI 助手，规定**架构不变量、编码、测试、文档与安全**要求。
> 产品定位、里程碑与文档索引见 `README.md`；接口细节见 `docs/接口文档.md`。

---

## 1. 项目定位

Echo 是一个 **Agent 驱动的 Live2D AI 伴侣**：

- **Agent（大脑）**：工具调用、长期记忆、结构化输出 `{reply, emotion}`
- **Live2D（身体）**：表情与口型由 Agent 事件流驱动
- **语音（感官）**：VAD / ASR / TTS，是它的耳朵和嘴

里程碑：M1 感官层 ✅ ｜ M2 Agent 大脑 ✅ ｜ M3 Live2D 身体 ⏳ ｜ M4 实时性与体验（流式、AEC、指标）

---

## 2. 架构不变量（改动必须遵守）

1. **组件只依赖接口**：`VADInterface` / `ASRInterface` / `LLMInterface` / `TTSInterface`；
   禁止一个组件直接调用另一个组件的具体实现。
2. **新增后端 = 新文件 + 装饰器 + 配置**：`@register_xxx("名字")` 注册后改 `conf.yaml` 即可；
   禁止修改工厂或管线来适配某个具体后端。
3. **一切可变参数走配置**：`conf.yaml` + Pydantic 校验；禁止在业务代码里硬编码模型名、阈值、路径。
4. **实例只能由 `ServiceContext` 创建**：管线通过注入获得组件，禁止在管线里 `new` 组件。
5. **阻塞调用必须下沉线程池**：CPU 推理与阻塞 IO 一律 `asyncio.to_thread` 包装，保持事件循环可响应。
6. **对外只发事件**：状态变化通过 `on_event(kind, payload)` 发出，`kind` 取值见接口文档；
   禁止让上层直接读内部字段来感知状态。
7. **采样率统一 16kHz / 单声道 / float32**：以 `ASRInterface.SAMPLE_RATE` 等常量为唯一来源。
8. **采集与播放的互斥策略只由 `duplex_mode` 决定**：禁止在别处私自启停麦克风流。

## 3. 目录约定

| 目录 | 职责 | 禁止事项 |
|------|------|---------|
| `src/echo/{vad,asr,llm,tts}/` | 四类能力组件（接口 + 实现 + 工厂） | 不放业务编排 |
| `src/echo/agent/` | Agent 大脑：工具注册表、工具调用循环、情绪解析 | 不碰音频 |
| `src/echo/pipeline/` | 编排：采集/VAD 与 应答两条并发流水线、打断、双工 | 不直接调用模型 HTTP |
| `src/echo/audio/` | 麦克风采集与播放 | 不做 VAD 判断 |
| `src/echo/memory/` | 对话历史与长期事实记忆 | 不做检索算法之外的业务 |
| `tests/` | 全部 mock 化测试 | 不依赖网络/声卡/真实模型 |
| `benchmarks/` | 可复现的延迟测量脚本与结果 | 不写猜测数字，必须实测 |
| `docs/` | 需求/架构/接口/调用链/Bug/规范 | 与代码同步更新 |

## 4. 编码规范

- 注释、文档、日志一律**中文**；标识符、关键字保持英文。
- 公开函数与类写 docstring；关键分支写"为什么这么做"，而不是复述代码。
- **错误信息必须可执行**：告诉使用者"怎么办"（例如缺依赖给安装命令、缺 Key 给配置路径）。
- 日志统一前缀，便于排查：`[麦克风]` `[双工]` `[VAD]` `[管线]` `[统计]`。
- 禁止裸 `except`；仅允许两类例外，且必须转成可读文本或事件：
  ① 事件回调兜底；② 工具执行异常（回给模型）。
- 单文件超过 300 行考虑拆分；一个函数只做一件事。

---

## 5. 测试规范

1. 新增功能**必须**附带测试；测试文件命名 `tests/test_<模块>.py`。
2. 测试**不得**依赖网络、真实模型、声卡：用 mock 组件 + 可注入的假麦克风/假播放器/脚本化假模型。
3. 提交前必须 `python -m pytest tests -q` 全绿（当前 52 个用例）。
4. 真实调用（API、模型、edge-tts）只做**手工冒烟**，并把数字写进 `benchmarks/results.md`。
5. 修改 VAD、管线、双工、超时保护相关逻辑时，必须同步更新或新增防回归测试。

---

## 6. 文档同步要求

改代码时必须同步对应文档，不允许出现"文档说的和代码不一样"：

| 改动类型 | 必须更新 |
|---------|---------|
| 接口签名、配置字段、CLI 参数 | `docs/接口文档.md` |
| 架构分层、并发模型、事件流 | `docs/架构设计.md` + `docs/调用链.md` |
| 需求状态、里程碑 | `docs/需求文档.md` + `README.md` 里程碑表 |
| 修掉一个真实 bug | `docs/真实Bug笔记.md`（现象/假设/证据/根因/修复/防回归）+ 对应测试 |
| 性能数字变化 | `benchmarks/results.md` |
| 新增/删除模块 | 本文件第 3 节目录表 + `docs/架构设计.md` 模块职责表 |

## 7. 安全红线

1. **密钥只放 `.env`**（已被 `.gitignore` 忽略）；`.env.example` 永远只写占位符 `sk-xxxx`。
2. 禁止提交 `models/`、`outputs/`、`.venv/`、真实录音。
3. 每次对外发布前运行 `tools/export_public_repo.py`——它会做课号残留检查与**明文密钥扫描**，
   发现 `sk-` 开头的长串会直接中止导出。
4. 一旦发生密钥泄露：立即轮换 Key → 清理受控文件 → 在 `docs/真实Bug笔记.md` 记录事故与预防措施。

## 8. 常用命令

```bash
# 运行（自动使用项目 venv）
.\run.bat --mode console                  # 语音对话（默认 half 双工）
.\run.bat --mode agent --text "现在几点？北京天气怎么样？"
.\run.bat --mode mic --seconds 10         # 麦克风诊断：实时 dB / 语音概率 / 自适应阈值
.\run.bat --mode record --seconds 6       # 录音，随后可用 --mode asr 验证识别

# 测试与基准
python -m pytest tests -q                 # 全部 mock 测试（当前 52）
python benchmarks/benchmark_once.py --text "用一句话介绍你自己" --repeat 3
```

## 9. 提交与发布规范

- 提交信息用中文，一句话说明"做了什么"，一次提交只做一类改动。
- 提交前确认 `pytest` 全绿；涉及音频行为的手工验证结论一并写进提交信息或文档。
- **仓库分工**：学习仓库（开发与记录，含学习资料、设计评审与面试手册）→ 通过
  `tools/export_public_repo.py` 生成公开仓库（只含产品代码与产品文档）。
  禁止在两个仓库之间手工双向修改；公开仓库的内容以导出脚本为准。

## 10. 已知缺陷与路线

完整清单见 `docs/与Pipecat对照评审.md`（内部文档）。当前最重要的四条：

1. **无 AEC**：外放可能自打断，当前用 `half` 模式规避，计划接 WebRTC AEC 或 Koala/Krisp；
2. **非流式**：TTS 整句合成约 2.7s、工具调用 3 次往返约 6.9s，计划分句流式 TTS → LLM 流式 → 工具并行；
3. **轮次判停只靠静音计数**：计划抽象为可插拔策略（静音 / 时长 / 语义）；
4. **Live2D 未接入**：M3 任务，事件流（thinking/tool_call/speech/emotion）已就绪。
