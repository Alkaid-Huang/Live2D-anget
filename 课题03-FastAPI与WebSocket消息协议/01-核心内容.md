## 3. 核心模型：WebSocket vs HTTP

**【类比/解释】** HTTP 像是打电话给客服——每次都要"拨号→接通→说完→挂断"。WebSocket 像是开了一条对讲机频道——接通后一直开着，双方随时说话，直到有人关机。

```
HTTP（短连接）                          WebSocket（长连接）

客户端 ──请求──→ 服务器                  客户端 ──握手──→ 服务器
客户端 ←──响应── 服务器                  客户端 ←──确认── 服务器
客户端 ──请求──→ 服务器                  ┌──────────────────┐
客户端 ←──响应── 服务器                  │  双向实时通信      │
客户端 ──请求──→ 服务器                  │  客户端 ⇄ 服务器   │
...                                     │  随时发消息        │
每次都要重新建立连接                     └──────────────────┘
                                        客户端 ──关闭──→ 服务器
```

**【事实】** Echo 的语音管线需要**持续双向通信**——前端不断发音频数据给后端，后端不断发回复给前端。HTTP 每次请求都要握手，开销太大。WebSocket 一次握手后保持连接，延迟在毫秒级。[$TRAE_REF](https://fastapi.tiangolo.com/advanced/websockets/)

## 4. 关键概念与例子

### 4.1 FastAPI WebSocket 最小示例

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()


@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    # 第一步：接受连接
    await websocket.accept()
    print("客户端已连接")

    try:
        while True:
            # 接收消息
            data = await websocket.receive_text()
            # 回复消息
            await websocket.send_text(f"服务端收到: {data}")
    except WebSocketDisconnect:
        print("客户端已断开")
```

**【事实】** `WebSocketDisconnect` 异常**必须处理**——客户端关浏览器、断网、刷新页面都会触发它。不处理会导致服务端崩溃。[$TRAE_REF](https://websocket.org/guides/frameworks/fastapi/)

### 4.2 消息协议设计 —— 本课的核心 ⚡设计4

#### 4.2.1 第一性原理：为什么是"单连接 + type 路由"？

在设计前后端通信时，有三种可选方案。我们逐一推导为什么 Open-LLM-VTuber 选择了"单条 WebSocket + type 字段路由"：

| 方案 | 做法 | 问题 |
|------|------|------|
| A. 多条连接 | 文字一条 WS、音频一条 WS、控制一条 WS | 连接数随消息类型爆炸；每条都要握手，资源浪费；前端要维护多个连接对象 |
| B. HTTP 轮询 | 客户端反复问"有新消息吗" | 延迟高（服务端有消息也得等客户端来问）；空轮询浪费带宽；无法服务端主动推送 |
| C. 单 WS + type 路由 | 一条连接，所有消息加 `type` 字段区分 | 连接复用率最高；服务端可主动推送；只需一套收发逻辑 ✅ |

**【推导结论】** 方案 C 胜出的本质：WebSocket 是**全双工长连接**，一条连接足以承载双向、多类型消息，再用 `type` 字段当"分拣标签"即可区分用途。这比"为每种消息开一条连接"省资源，比"轮询"低延迟。**一条连接走天下，type 字段当路标**——这就是 Echo 也采用此方案的根本原因。

> 💡 **核心结论（后续课题会反复引用）**：课题04 的管线编排、课题16 的打断信号链，都建立在这个"单连接 + type 路由"的基础上。打断信号（interrupt）就是通过 `type: "control"` 在**同一条连接**里逆流传播的——不需要为打断单独开连接。

**【类比/解释】** 一条 WebSocket 连接就像一根水管，你可以往里面流自来水、可乐、橙汁。但接收方怎么知道这杯是水还是可乐？你需要给每杯液体贴个标签——这就是消息协议中 `type` 字段的作用。

Open-LLM-VTuber 的真实现状：所有消息走同一条 WebSocket，用 `type` 字段区分：

```json
// 文字消息
{"type": "text", "content": "你好，Echo"}

// 控制指令
{"type": "control", "action": "start_recording"}

// 错误消息
{"type": "error", "message": "LLM 响应超时"}

// 音频数据（二进制帧，不是 JSON）
[二进制音频字节]
```

**你的 Echo 也用这个模式**——前端和后端之间只有一条 WebSocket，所有消息通过 `type` 字段路由到不同的处理逻辑。

### 4.3 消息分发的核心模式

服务端收到消息后，需要做三件事：**解析 JSON → 读 `type` 字段 → 分发到对应处理逻辑**。这个模式的核心骨架如下：

```python
# 这是教学骨架，不是完整代码！不要直接复制。
# 你的任务代码在第 6 节。

@app.websocket("/ws")
async def handler(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            raw = await websocket.receive_text()       # ① 收消息
            msg = json.loads(raw)                      # ② 解析 JSON
            msg_type = msg.get("type", "unknown")      # ③ 读 type 字段

            if msg_type == "text":
                ...   # 处理文字消息
            elif msg_type == "control":
                ...   # 处理控制指令
            elif msg_type == "ping":
                ...   # 处理心跳
            else:
                ...   # 未知类型 → 报错

    except WebSocketDisconnect:
        ...   # 客户端断开 → 清理
```

**这就是整个服务端的核心逻辑**——一个 `while True` 循环里，接收 → 解析 → 分发 → 回复。你第 6 节的任务就是把这个骨架填满。

### 4.4 前端是怎么连上来的

前端通过浏览器内置的 `WebSocket` 对象连接后端，流程如下：

```
前端 (client.html)                          后端 (server.py)
─────────────────                          ────────────────
new WebSocket("ws://localhost:8000/ws")
    │
    └────────── 握手请求 ──────────────→  @app.websocket("/ws")
                                             │
    ←────────── 握手确认 ──────────────     await websocket.accept()
    │
    │  ws.onopen 触发（连接成功）
    │
    │  ws.send(JSON.stringify(msg))        await websocket.receive_text()
    │  ──────── {"type":"text",...} ────→      │
    │                                         json.loads() → 分发处理
    │  ←─────── {"type":"text",...} ────    await websocket.send_text(...)
    │  ws.onmessage 触发
    │
    │  用户关闭页面
    │  ──────── 连接断开 ──────────────→  WebSocketDisconnect 异常
    │  ws.onclose 触发                        print("客户端已断开")
```

**关键点**：前端只需要 3 个 API —— `new WebSocket(url)` 建立连接、`ws.send(json)` 发消息、`ws.onmessage` 收消息。你不需要写前端代码，第 6 节已经提供了完整的 `client.html`，直接保存即可。

## 5. 常见坑

### 坑 1：忘记 `await websocket.accept()`

```python
@app.websocket("/ws")
async def ws(websocket: WebSocket):
    # ❌ 忘记 accept()，直接 receive_text() 会报 RuntimeError
    data = await websocket.receive_text()
```

### 坑 2：不处理 `WebSocketDisconnect`

```python
while True:
    data = await websocket.receive_text()  # ❌ 客户端断开时直接崩溃
```

### 坑 3：JSON 解析异常不捕获

```python
msg = json.loads(raw)  # ❌ 如果 raw 不是合法 JSON，直接崩溃
```

### 坑 4：在消息处理循环中做耗时操作

```python
while True:
    data = await websocket.receive_text()
    # ❌ 在 receive 和下一个 receive 之间做了耗时同步操作
    time.sleep(2)  # 这会阻塞整个事件循环，其他连接全部卡住
    await websocket.send_text(f"回声: {data}")
```

**【事实】** WebSocket 是全双工的，send 和 receive 可以交替进行。但如果在消息处理循环中混入同步阻塞操作（如 `time.sleep`、大文件读写），整个事件循环都会被卡住，所有连接的客户端都会超时。正确做法是耗时操作用 `await` 异步版本。[$TRAE_REF](https://fastapi.tiangolo.com/advanced/websockets/)

### 坑 5：前端用 `ws://` 但页面是 `https://`

```
浏览器安全策略：HTTPS 页面只能用 wss://，不能用 ws://
本地开发用 http://localhost 打开页面即可
```

## 6. 你的任务：实现 Echo 消息协议服务器

> **4.3 节的骨架就是你要实现的东西。** 下面把骨架拆成 9 个 TODO，每个都附了方法说明，照着填就行。

你需要实现一个 FastAPI WebSocket 服务器，支持以下消息协议：

| 消息类型 | 方向 | 格式 | 服务端行为 |
|---------|------|------|-----------|
| `text` | 客户端→服务端 | `{"type":"text","content":"..."}` | 回复 `{"type":"text","content":"回声: ..."}` |
| `control` | 客户端→服务端 | `{"type":"control","action":"start"/"stop"}` | 回复 `{"type":"control","action":"...","status":"done"}` |
| `ping` | 客户端→服务端 | `{"type":"ping"}` | 回复 `{"type":"pong"}` |
| 非法 JSON | 客户端→服务端 | 非 JSON 字符串 | 回复 `{"type":"error","message":"..."}` |
| 未知 type | 客户端→服务端 | `{"type":"xxx"}` | 回复 `{"type":"error","message":"未知消息类型: xxx"}` |

### 本课涉及的新方法速查表

| 方法 | 所属对象 | 作用 | 参数 | 返回值 |
|------|---------|------|------|--------|
| `@app.websocket("/ws")` | FastAPI `app` | 装饰器，把函数注册为 WebSocket 端点 | 路径字符串 | 无（装饰器） |
| `await websocket.accept()` | `WebSocket` | 接受客户端的连接请求，**必须最先调用** | 无 | `None` |
| `await websocket.receive_text()` | `WebSocket` | 等待并接收客户端发来的文本消息 | 无 | `str`（客户端发来的字符串） |
| `await websocket.send_text(data)` | `WebSocket` | 向客户端发送文本消息 | `data: str`（要发送的字符串） | `None` |
| `json.loads(s)` | `json` 模块 | 把 JSON 字符串解析为 Python 字典 | `s: str` | `dict` / `list` / `str` / `int` 等 |
| `json.dumps(obj)` | `json` 模块 | 把 Python 对象转为 JSON 字符串 | `obj`（要序列化的对象） | `str` |
| `dict.get(key, default)` | `dict` | 安全地取字典的值，键不存在时返回默认值 | `key`（键名）, `default`（默认值） | 键对应的值或默认值 |
| `print(...)` | 内置函数 | 打印到控制台 | 任意内容 | `None` |
