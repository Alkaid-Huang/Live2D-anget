## 3. 核心模型：WebSocket vs HTTP

**【类比/解释】** HTTP 像是打电话给客服——每次都要"拨号→接通→说完→挂断"。WebSocket 像是开了一条对讲机频道——接通后一直开着，双方随时说话，直到有人关机。

```
HTTP（短连接）                          WebSocket（长连接）

客户端 ──请求──→ 服务器                  客户端 ──握手──→ 服务器
客户端 ←──响应── 服务器                  客户端 ←──确认── 服务器
客户端 ──请求──→ 服务器                  ┌──────────────────┐
客户端 ←──响应── 服务器                  │  双向实时通信      │
客户端 ──请求──→ 服务器                  │  客户端 ⇄ 服务器   │
...                                     │  随时发消息        │
每次都要重新建立连接                     └──────────────────┘
                                        客户端 ──关闭──→ 服务器
```

**【事实】** Echo 的语音管线需要**持续双向通信**——前端不断发音频数据给后端，后端不断发回复给前端。HTTP 每次请求都要握手，开销太大。WebSocket 一次握手后保持连接，延迟在毫秒级。[$TRAE_REF](https://fastapi.tiangolo.com/advanced/websockets/)

## 4. 关键概念与例子

### 4.1 FastAPI WebSocket 最小示例

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()


@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    # 第一步：接受连接
    await websocket.accept()
    print("客户端已连接")

    try:
        while True:
            # 接收消息
            data = await websocket.receive_text()
            # 回复消息
            await websocket.send_text(f"服务端收到: {data}")
    except WebSocketDisconnect:
        print("客户端已断开")
```

**【事实】** `WebSocketDisconnect` 异常**必须处理**——客户端关浏览器、断网、刷新页面都会触发它。不处理会导致服务端崩溃。[$TRAE_REF](https://websocket.org/guides/frameworks/fastapi/)

### 4.2 消息协议设计 —— 本课的核心 ⚡设计4

**【类比/解释】** 一条 WebSocket 连接就像一根水管，你可以往里面流自来水、可乐、橙汁。但接收方怎么知道这杯是水还是可乐？你需要给每杯液体贴个标签——这就是消息协议中 `type` 字段的作用。

Open-LLM-VTuber 的真实现状：所有消息走同一条 WebSocket，用 `type` 字段区分：

```json
// 文字消息
{"type": "text", "content": "你好，Echo"}

// 控制指令
{"type": "control", "action": "start_recording"}

// 错误消息
{"type": "error", "message": "LLM 响应超时"}

// 音频数据（二进制帧，不是 JSON）
[二进制音频字节]
```

**你的 Echo 也用这个模式**——前端和后端之间只有一条 WebSocket，所有消息通过 `type` 字段路由到不同的处理逻辑。

### 4.3 实现带协议的服务端

```python
import json
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()


@app.websocket("/ws")
async def echo_with_protocol(websocket: WebSocket):
    await websocket.accept()
    print("客户端已连接")

    try:
        while True:
            raw = await websocket.receive_text()
            try:
                msg = json.loads(raw)
                msg_type = msg.get("type", "unknown")

                if msg_type == "text":
                    content = msg.get("content", "")
                    await websocket.send_text(json.dumps({
                        "type": "text",
                        "content": f"回声: {content}"
                    }))

                elif msg_type == "control":
                    action = msg.get("action", "")
                    await websocket.send_text(json.dumps({
                        "type": "control",
                        "action": action,
                        "status": "done"
                    }))

                elif msg_type == "ping":
                    await websocket.send_text(json.dumps({"type": "pong"}))

                else:
                    await websocket.send_text(json.dumps({
                        "type": "error",
                        "message": f"未知消息类型: {msg_type}"
                    }))

            except json.JSONDecodeError:
                await websocket.send_text(json.dumps({
                    "type": "error",
                    "message": "消息格式错误，需要 JSON"
                }))

    except WebSocketDisconnect:
        print("客户端已断开")
```

## 5. 常见坑

### 坑 1：忘记 `await websocket.accept()`

```python
@app.websocket("/ws")
async def ws(websocket: WebSocket):
    # ❌ 忘记 accept()，直接 receive_text() 会报 RuntimeError
    data = await websocket.receive_text()
```

### 坑 2：不处理 `WebSocketDisconnect`

```python
while True:
    data = await websocket.receive_text()  # ❌ 客户端断开时直接崩溃
```

### 坑 3：JSON 解析异常不捕获

```python
msg = json.loads(raw)  # ❌ 如果 raw 不是合法 JSON，直接崩溃
```

### 坑 4：在消息处理循环中做耗时操作

```python
while True:
    data = await websocket.receive_text()
    # ❌ 在 receive 和下一个 receive 之间做了耗时同步操作
    time.sleep(2)  # 这会阻塞整个事件循环，其他连接全部卡住
    await websocket.send_text(f"回声: {data}")
```

**【事实】** WebSocket 是全双工的，send 和 receive 可以交替进行。但如果在消息处理循环中混入同步阻塞操作（如 `time.sleep`、大文件读写），整个事件循环都会被卡住，所有连接的客户端都会超时。正确做法是耗时操作用 `await` 异步版本。[$TRAE_REF](https://fastapi.tiangolo.com/advanced/websockets/)

### 坑 5：前端用 `ws://` 但页面是 `https://`

```
浏览器安全策略：HTTPS 页面只能用 wss://，不能用 ws://
本地开发用 http://localhost 打开页面即可
```
